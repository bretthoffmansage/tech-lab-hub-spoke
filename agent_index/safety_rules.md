# Safety Rules

Hard rules for any agent or script operating on this knowledge base.

1. **Do not modify raw transcripts.** The `.txt` files in the project root
   (and anything in `raw_transcripts/`) are read-only source material. All
   outputs go to `processed/`, `database/`, or `exports/`.

2. **Do not invent source facts.** Every claim, question, hook, or excerpt
   must trace to actual chunk text. If the archive doesn't say it, the answer
   is "not found in the archive," not a plausible guess.

3. **Do not claim mock extraction is final.** While
   `extraction_provider: "mock"` records exist, label outputs as
   placeholder/workflow-test quality. Real LLM extraction replaces them.

4. **Do not cite speakers or timestamps.** The transcripts have neither.
   Never write "the founder said" or "at 32:10" — attribute only to
   `source_file` and `chunk_id`.

5. **Do not present generated questions as verbatim transcript quotes.**
   Reworded or generated material (right-fit-client questions, angles) must
   be distinguishable from verbatim lines (`quotable_lines`,
   `source_excerpts`). When quoting, quote exactly.

6. **Keep generated assets traceable.** Every asset shown to a user should
   carry `source_file` + `chunk_id` when available; if traceability is
   missing, say so rather than dropping the caveat.

7. **Do not hand-edit pipeline outputs.** JSONL files and the SQLite database
   are regenerated by scripts; manual edits will be silently lost on rerun.

8. **Honest method labels.** Topic discovery and search are keyword/alias
   matching. Do not describe them as semantic understanding or AI analysis.
